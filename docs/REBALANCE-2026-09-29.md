## Finding

Pythian has a substantial reusable Pascal synthesis and WFC foundation. The
remaining bottleneck is trustworthy musical evidence flowing into a useful,
repeatable learned style. Progress reports have mixed mechanism delivery,
research feasibility, source qualification and product acceptance. The former 71.55% engineering ledger over-weighted infrastructure and under-weighted
the unclosed workflows. The user's authorization to rebalance credit retires that
basis. The new outcome ledger is **45.50%**; it remains a scope judgment, not
measured readiness, general transcription accuracy or an accepted many-hour style.

This audit inspected the project/standards, all open task contracts and accepted
task ledger, current milestone and handoff records, the primary architecture,
learning/style/evaluation contracts, and maintained source/build/package/test
entry points. [Codebase assessment](CODEBASE-ASSESSMENT.md) records concrete
source evidence and limits. This is a source and recorded-evidence assessment,
not a line-by-line defect proof, new benchmark or fresh listening verdict.

The public goal is an independently reusable Pascal audio synthesis library,
trustworthy supported musical learning from WAV, and caller-defined styles
that generate through granular WFC passes and survive selective blends and
further blends. **Chillwave, stoner rock and lofi are internal tests only.**
“Any style, any user” requires user-supplied identities, evidence and traits
without code changes; it does not promise accurate extraction of every
instrument, meter or mixture. Unsupported input must remain unknown or reject.

## Definition of a completed result

- A **dependable synthesis result** has its declared numerical, ownership,
  boundary, replay and actual listening evidence. NS-2's accepted built-in scope is preserved;
  caller extension conformance remains open, not every conceivable technique or setting.
- A **trustworthy learned provider** saves actual audio-derived predictions
  before independent scoring, preserves unknown coverage and source clocks,
  passes frozen per-case accuracy gates and reaches a maintained consumer.
  Raw observations, references and prediction agreement are distinct.
- A **bounded learned style** can be learned, saved, reloaded, generated and
  edited through the supported contract, with measured and heard benefit
  against matched baselines. Authored dimensions are explicit.
- A **many-hour style** adds complete required musical dimensions, independent
  multi-recording coverage, whole-pipeline budgets, recovery, sustained quality
  and advantage over single-recording and shuffled controls.
- **Reusable blending** selects or weights declared dimensions, preserves
  independent state and original source contributions, exposes contradictions,
  reloads and remains a valid parent for another blend and generation.
- **Independent delivery** requires the actual exact-revision package to work
  outside the development checkout. An agent rebuilding in another local
  directory proves isolation, not an independent user's verdict.

No new provider threshold is invented by this planning pass. Existing fixed
gates remain binding. Where a future provider still lacks numeric criteria,
its first deliverable must freeze supported cases, reference quality, denominators,
thresholds and cost before candidate scoring. Missing required truth is an
explicit external/reference blocker, not an invitation to tune until something
looks plausible.

All required tasks must pass before 100%, including external outcomes. There is
no finite task list or finite dataset that proves every possible style, recording,
user or future platform. The operational any-user requirement is a documented
caller extension path plus genuine new-caller recorded-style acceptance, with
unsupported cases visible. A missing required trait may not be relabelled
optional/unsupported after results are seen.

Likewise, no arbitrary project count automatically proves “de facto standard.”
The adoption task must establish a prospective defensible ecosystem scope and
evidence threshold, real unrelated maintained production use across an update,
and whether the resulting independent evidence actually supports the stated
standard claim. If that evidence or the claim's acceptance definition is absent,
the task and full goal stay open. No task authoring, convenient smaller claim,
or engineering-only subtotal may be reported as 100% of the original goal.

## WFC is integral, with explicit repository ownership

The complete product pairs the independent synthesis core with WFC composition
and audio generation. The core-only package must continue to work without WFC;
that isolation does not make WFC an optional completion goal. Both package
closures, genuine WFC constraint passes, caller providers, selective edits and
repeated blended generation have required owners.

The boundary audit found concrete extensibility gaps in Pythian's closed
provider vocabulary and audio contracts. Existing WFC sequence, graph, selective
repair and fragment-composition contracts cover the generic mechanisms needed
by the inspected paths; no minimal generic-core failure was found. The separate
local WFC checkout was inspected read-only. No upstream branch or pin changed.
See the [source audit](CODEBASE-ASSESSMENT.md) for evidence and limits.

Pythian owns audio clocks, semantic providers, sound, admission, style provenance
and integration. A reproduced generic solver/graph gap belongs in the separate
WFC repository on a new branch, with user notification and linked integration
evidence. Never patch the vendored checkout. The
[architecture boundary](ARCHITECTURE.md#core-and-wfc-symbiosis) and
[cross-repository workflow](TASKFLOW.MD#cross-repository-wfc-gaps) make that rule
part of ordinary task selection.
