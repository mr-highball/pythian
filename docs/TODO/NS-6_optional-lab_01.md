**Description:**

Restore a reachable optional consumer for the existing authored/experimental
musical controls. The simple Library→Selection→Generate replacement left the old
instrumental and batch UI classes unreferenced. Historical browser evidence does
not prove that key/tempo, expression and editable affect helpers are reachable
today. Preserve the simple main flow; experimentation is an optional laboratory,
not a setup or labeling requirement before ordinary generation.

Primary attribution: NS-6. These four repair units cover the new UI consumer and
removal of superseded presentation, not reimplementation or additional credit
for existing control algorithms. The parent graph-controls estimate remains seven.

**Acceptance Criteria:**

- AC1: Open optional musical experiments from Studio without changing the three
  main steps or requiring source recordings. Expose actual key/tempo, per-role
  pitch/activity/expression and editable energy/density/tension mappings through
  the existing Pascal controls and native instrumental job contracts.
- AC2: Clearly distinguish authored/operator/experimental inputs from learned
  observations. Save/reopen the actual settings and lineage. Applying a helper
  only changes visible settings; generation requires an explicit action and
  feedback never silently trains.
- AC3: Produce actual instrumental output and retain useful failure/cancel/retry
  behavior. Verify key/tempo and mapped expression/activity in native receipts
  and desktop/phone use, including contextual help without scroll jumps.
- AC4: Reuse useful existing form/transport behavior and the primary library.
  Remove superseded orphan batch/UI code after checking its consumers; preserve
  historical evidence. Update current instructions to describe reachable paths.
