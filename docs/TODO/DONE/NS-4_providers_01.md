[Task index](../README.md) · [Task flow](../../TASKFLOW.MD) · [North star](../../MILESTONES.md#ns-4)

**Description:**

Prove caller extension of the musical provider contract, beyond supplying a new corpus label to the fixed built-in semantic vocabulary. A Pascal caller can introduce a declared provider/role or trait vocabulary, compose it through actual WFC dependencies, control it, save it and reuse its blends without modifying Pythian.

The public registry is borrowed synchronously at each admission or reconstruction
entry point. Accepted sessions own detached binding/configuration and decoded
choices; their generation works after registry/codec destruction. Styles retain
serialized bindings, models and evidence, and new session admission needs a live
registry. Later replacement or parent reload receives one explicitly. One shared
operation context spans recursive parents, validation, constructors and internal
session creation; no nested budget reset is allowed. Codec identity, canonical
configuration, units and unknown meaning join ordered token text in vocabulary
identity. Original source/run identities and boundaries retain their separate
evidence checks and do not enter that meaning digest. The current style format
advances with these bindings; no legacy reader or executable payload is added.

Declared limits are 64 registry entries, 128 ASCII identity bytes, 64 KiB
configuration per provider, 4096 UTF-8 token/payload bytes each, 262144 codec
dispatches, 16777216 declared work units, 32 MiB aggregate callback
configuration/token/payload I/O and 8 MiB cumulative admitted decoded payload
per operation. These counters do not mean total internal work/process memory
or current resident payload. Known input/configuration and
declared cost are checked before dispatch; callback results are checked before
copy/retention. Immutable snapshots detach mutable arrays. These limits do not
bound execution or allocations inside arbitrary caller code: purity,
determinism, truthful cost and declared meaning remain caller obligations.
Effective pinned WFC bounds are 1024 public tokens and 1024 states, provider
model order at most 64, alongside
eight Pythian layers, 1024 cells, 16777216 projection work, 32 MiB style bytes
and eight ancestry nodes.

Closing evidence is maintained Pascal conformance on stable Win32/Win64 and the
exact-revision Linux/package matrix: actual dependent WFC passes; typed controls
and failed replacement preservation; missing/incompatible nested registration;
overflow-safe aggregate rejection across providers/parents; source-independent
meaning identity; save/reload/selective blend/further blend; original evidence

**Acceptance Criteria:**

- AC1: Expose a maintained public extension contract binding caller provider identity, supported vocabulary, clock, source evidence, dependencies, compatibility and resource bounds. Demonstrate a provider or trait vocabulary not hardcoded into the built-in enum through external Pascal units; merely renaming an existing provider is insufficient.
- AC2: Use the caller provider in actual multi-pass WFC generation with typed preferences and hard locks. Compatible replacement preserves unrelated accepted states; contradictory or incompatible replacement rejects without mutation.
- AC3: Save/reload the extension's parameters, evidence, vocabulary/time mappings and source contributions in the current style format, using a caller-supplied codec or declared registration interface. Missing or incompatible registrations reject explicitly; no silent conversion to a built-in type or unverified executable payload.
- AC4: Perform selective blend and further blend containing the extension, retaining chosen/weighted traits, dependencies, original evidence and deterministic native audio. Reload a derived result and use it as a parent again.
- AC5: An external consumer builds and runs this example against the minimal package without library or WFC edits. Publish the exact extensibility boundary, numeric work/state limits, failure behavior and supported target evidence. If arbitrary semantic schemas remain unsupported, the goal's public claim must name that limit rather than claim unbounded custom providers.
