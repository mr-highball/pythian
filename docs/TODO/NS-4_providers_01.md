**Acceptance Criteria:**

- AC1: Expose a maintained public extension contract binding caller provider identity, supported vocabulary, clock, source evidence, dependencies, compatibility and resource bounds. Demonstrate a provider or trait vocabulary not hardcoded into the built-in enum through external Pascal units; merely renaming an existing provider is insufficient.
- AC2: Use the caller provider in actual multi-pass WFC generation with typed preferences and hard locks. Compatible replacement preserves unrelated accepted states; contradictory or incompatible replacement rejects without mutation.
- AC3: Save/reload the extension's parameters, evidence, vocabulary/time mappings and source contributions in the current style format, using a caller-supplied codec or declared registration interface. Missing or incompatible registrations reject explicitly; no silent conversion to a built-in type or unverified executable payload.
- AC4: Perform selective blend and further blend containing the extension, retaining chosen/weighted traits, dependencies, original evidence and deterministic native audio. Reload a derived result and use it as a parent again.
- AC5: An external consumer builds and runs this example against the minimal package without library or WFC edits. Publish the exact extensibility boundary, numeric work/state limits, failure behavior and supported target evidence. If arbitrary semantic schemas remain unsupported, the goal's public claim must name that limit rather than claim unbounded custom providers.
